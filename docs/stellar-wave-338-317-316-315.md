# Stellar Wave — triage issues #338, #317, #316, #315

Wave branch: `feat/stellar-drips-wave-338-317-316-315`

## #338 — feat(contracts): circle frequency-based auto-round advancement
- State: triaged this wave. `CircleFrequency` (Daily/Weekly/Biweekly/Monthly) exists in
  `packages/circle/src/types.rs` but is referenced nowhere else; round advancement is manual
  via `trigger_payout` (`packages/circle/src/contract.rs`).
- Acceptance criteria: store frequency in `CircleConfig`; add `check_and_advance_round()`
  advancing on frequency + timestamps; integrate with contribution deadline enforcement;
  tests per frequency type. Complexity: High.

## #317 — Reputation-registry scoring hardcoded non-configurable parameters
- `packages/reputation-registry/src/scoring.rs` `record_on_time_payment` hardcodes base 10,
  streak bonus 5/step (max 50), volume 1 per 100 USDC (max 20), cap 1000.
- Suggested fix: store scoring parameters in a governance-updatable `ScoringConfig`.

## #316 — Circle execute_leave expensive load_round_details for many rounds
- `packages/circle/src` `execute_leave` path reads all round data from storage; expensive for
  100+ rounds. Suggested fix: caching or pagination. Low priority.

## #315 — Circle payout sqrt precision for large pool balances
- `packages/circle/src` payout uses integer-truncated `sqrt` for Oracle reward estimation;
  error grows for pool balances > 10^18. Suggested fix: fixed-point sqrt or wider acceptance
  window. Medium priority.
